# Conditional Positioning

A resume is not a record of what someone did — it is an argument that they are the right fit for **one specific target role**. "Conditional" means every choice (summary, bullet emphasis, project order, which experience leads) is conditioned on that target. Establish the target role first; if it is not stated, ask for it before evaluating or rewriting.

## The eight checks, collapsed

Candidates often list many overlapping asks. Collapse them into five real, non-redundant tests. Do not grade overlapping asks as independent passes.

1. **Bullet quality.** No generic lines ("passionate about technology, eager to learn"). Every bullet names a mechanism and the consequence it produces — ideally with a number. Model: *"Capped the agent at 20 loops with state transitions, ending runaway runs that drained user credit."* not *"Worked on agent reliability."*
2. **Summary = positioning + hook.** 2–4 lines that establish all four: **who** you are, **what** you are targeting, **what value** you bring, **proof**. The opening line must carry identity + target — do NOT bury them under a clever hook. A strong problem-framed hook (a real failure mode, a sharp one-liner) goes *after* the identity line, not instead of it. Collapses the common "storytelling hook" and "2–3 line summary" asks into one block.
3. **Value pillars, role-tied.** The resume should repeat 3–4 consistent strengths that are the *right* ones for the target role, reinforced across summary, skills, and projects. Name them; check each project hits at least one. (This absorbs "positioning," "value pillars," and "relevance to role" — they are three angles on one question.)
4. **Proof stack.** Claims must be verifiable: live links, portfolio, repos, demos. Flag when the *most role-relevant* work is the *least* demo-able (e.g. the flagship AI project has GitHub only while a side project has the live link). Never fabricate links or metrics — flag the gap for the candidate to fill.
5. **Primary/secondary role balance.** Commit to ONE primary role across summary, skills, and the lead projects. Let a *deliberate, well-chosen* secondary show through — the one that best supports the primary (e.g. full-stack/service-layer under agentic-AI; data analysis under ML; design under frontend). The secondary must be *framed as supporting*, not left sitting as the only paid experience, or the resume reads as "X pivoting to Y" instead of "Y who can also do X."

## Method

1. **Lock the target role.** Ask if unstated.
2. **Score each of the five tests** as Pass / Partial / Fail, with the specific failing line quoted and a concrete fix. Produce a short scorecard table mapping the candidate's original asks to these tests.
3. **Rewrite to clear every test**, in this priority order:
   - Add one identity + target sentence to the top of the summary.
   - Reframe experience bullets to lead with transferable, role-relevant skills (bridge sentences work well: *"the same validation gate I now put in front of every agent run"*).
   - Reorder projects so the most role-relevant work leads; let the secondary-signal project close the list.
   - Add a closing summary clause that names the secondary as deliberate support (*"...so I ship the whole system, not just the prompt"*).
4. **One page.** Enforce a single page; tighten spacing, never cut substance to fit.

## Hard rules

- Never invent metrics, dates, employers, or links. If proof is missing, flag it as the candidate's one manual step.
- Keep placeholder URLs obvious and tell the user to supply the real LinkedIn/GitHub/Portfolio links.
- Pair with `write-without-ai-tells` for wording so the final text does not read as machine-generated.
- For file output: a resume the user will submit is an ATS artifact — prefer a one-page `.docx` (plus PDF) and verify the rendered page before delivering.
